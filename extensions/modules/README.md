# SAO ZH 功能模組套件 1.1.0

擴充按**功能模組**組織，不是一個畫面一個插件。一個模組包含多個顯示入口、專屬詞條及共用相依；編譯成現有 V16 runtime 可讀的簽章規則，不需要更換核心 JAR。

## 這次的模組

| 模組 | 職責 | 攔截點 |
|---|---|---:|
| `shared-terms` | 跨模組共用術語與法／英別名 | 0（資料） |
| `dynamic-translation` | SAOUI 原生 TranslateClient 的名稱、描述、對話與系統訊息結果 | 13 |
| `items-economy` | 原生物品翻譯、登入獎勵、裝備屬性、跨服物品清單 | 8 |
| `quests-objectives` | 任務描述、目標、既有翻譯結果、追蹤 HUD 部分文字 | 5 |
| `codex-creatures` | 圖鑑分類、名稱、描述、世界名與掉落名稱 | 5 |
| `skills-progression` | 技能詳情名稱、描述欄位與屬性名 | 3 |
| `worlds-locations` | 跨服世界名稱、傳送點的標籤量測及繪製 | 4 |

總計 7 個模組、38 個文字攔截點，對應 10 個實際 SAOUI／SAOJob 類別。這些數字表示已驗證的程式入口，不代表所有文字已翻譯，亦不代表所有畫面已實機驗收。

## 核心、執行引擎和功能模組

- 安裝的 `SAO_ZH_Agent_v16.jar` 是固定小核心；本次沒有改其位元組或重新編譯。
- `SAO_ZH_Runtime_1.0.0.jar` 是外部執行引擎，負責受限腳本、簽章驗證、類別重新轉換與顯示投影。
- `modules/<功能>/module.json` 是可獨立維護的功能模組來源。
- 發布時將模組組成一份完整、一致的已簽章規則版本；**不是每個畫面各下載／各切一版**。
- 模組詞條只在該模組及明示相依者作用，不做全域無條件文字替換。

V15 舊有功能已放在外部相容 JAR；但這部分目前仍於啟動時載入，尚未全部拆成可獨立熱卸載模組。新版受限規則可熱更新；引擎或相容 JAR 的二進位更新仍暫存至下次啟動。不要把「核心外部化」誤認為所有底層變更都可無限制即時替換。

## 模組編寫與發佈

`tools/compose_modules.py` 是純作者端工具，不在玩家渲染迴圈執行、不需要玩家安裝 Python。它不含簽章私鑰，也不下載或執行 JavaScript。

1. 修改功能模組，增加多個實際已查證的 `return / argument / field / call` 入口。
2. 更新模組版本。保持 `dependencies` 的最低版本與共用字典明確。
3. 編譯成新 bundle，使用新的套件版本與遞增 sequence。
4. 以 framework 的 `ValidateRules` 對實際模組 JAR 驗證類別／方法／指令位置。
5. 使用既有 `client-framework/tools/sign_rules.py` 在維護者電腦簽章；私鑰不可上傳 GitHub。
6. 上傳 `extensions/v1/rules-<版本>.json`、簽章及已簽署的 stable 索引。客戶端驗證後自動熱套用。

例如從 repo 根目錄：

```powershell
py client-framework/tools/compose_modules.py extensions/modules --version 1.1.1 --sequence 102 --expires <未來Unix秒數> --out rules-1.1.1.json
```

上例的版本、sequence 與到期時間必須按實際新版本設定；不可覆蓋已發佈版本。正式簽章前仍必須做原生位元碼驗證與整合測試。

### 回退的兩種範圍

**整組立即回退：**執行現有 `saozh-rollback.cmd`，回復本機前一個已簽章規則版本並暫停自動升級；`saozh-refresh.cmd` 才恢復更新。

**僅回退某功能模組：**維護者將該模組的來源改回已知正常版本，保留其他模組最新版，再以新的套件 sequence 編譯、驗證、簽章及發佈。這樣不會降版其他功能，也不會繞過反降版驗證。

## 更新與互動狀態

對每次繪製都讀取的 String／Text 參數、回傳值、欄位讀取及方法結果，規則可在原介面物件繼續存在時生效。不修改原始資料模型，不替玩家發出關閉容器、交易或領獎封包。

**已先快取成行列表、圖片或固定布局的介面不保證立即重排。** 本輪沒有做通用 GUI 重建，也沒有解決全部拍賣換行問題。這些需要在相應功能模組增加可驗證的刷新／排版處理，不會自動用關閉再開啟容器代替。

## 效能與拒絕策略

編譯端拒絕相依循環、缺少模組、版本過舊、同位置重複攔截、錯誤占位符、未知指令及超出預算的資料。規則總上限沿用 runtime：128 個 hook、2 MiB 與每個 hook 8 條受限操作。

客戶端使用不可變的生效快照。只改詞條而未改攔截形狀時，不重新轉換類別；在 callback 中不連 GitHub、不解析 JSON。無法驗證的新版本不取代舊版；callback 出錯保留原值。這不等於保證 JVM／原生驅動永不崩潰。

## 本次測試證據與邊界

- 25 項 Python 模組組裝／輸入邊界測試。
- 同一 JVM 的 17 項功能模組熱更新與選擇性回退斷言，已有畫面物件的搜尋文字、捲動、選擇及拖曳參照不變。
- 實際 SAOUI 2.35.0／SAOJob 1.1.3 的 38 個 hook 位置驗證。
- 實際 Minecraft Text 樣式／子節點不變，10 個已載入原生類別可新增規則，再移除，外部相容功能仍在。
- 未在真實 Minecraft 畫面中逐介面操作驗收；任務行快取、拍賣自動分行、所有地圖與世界 Boss 內容尚未全部完成。

材質包繼續使用 SAOMCZHPACK v1.0.5 公開測試版。本次沒有重建或回退材質包，沒有修改啟動器、遊戲設定或 V15。
