# SAO ZH modular runtime v16
User goal: one small installed agent; SAO-specific translation, font/layout, startup splash and future method hooks are external. Compatible rule updates apply without restart; failures retain old text/snapshot. Preserve current interaction state; never close/reopen a server container automatically.
Architecture: small JDK bootstrap with pinned signing key; separately signed runtime engine and SAO compatibility extension; a stable bootstrap dispatch API; bounded declarative hook scripts updated atomically; exact String/Text return, argument, field-read and invocation-result targets; no arbitrary scripts/OS access.
Migration: existing V15 behavior is packaged externally as a startup compatibility module, not advertised as fully hot-unloadable. New bounded hook rules and text policies are hot-updateable including already-loaded classes. Runtime/compatibility binary replacements that cannot safely unwind are staged for next boot, with no manual agent replacement. Resource packs remain next-launch-only.
Safety: signed manifests and hash verified files; class/method and return-type guards; no schema changes; deny JDK/kernel/loader internals; bounded inputs, callbacks, text sizes and cache; fail-open dispatch, recursion guard, rollback on retransform failure. Never promise a JVM crash cannot occur.
Performance: immutable snapshots, target class indexing, precompiled operations, no JSON/network/file IO from drawing callbacks, bounded lookup cache and background polling.
Evidence required: reproduce new-rule missing support first; real JVM changes methods that were loaded before a rule existed; field projection preserves screen identity/selection/input; invalid target, rejected signer and bad update preserve old output; remove/rollback restores originals; tests use packaged JARs, not dev resources.
