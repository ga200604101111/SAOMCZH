# 全詞庫字形修復與文字／圖示隔離

日期：2026-10-30。狀態：已實作及通過離線驗證的開發候選，未簽章、未部署遊戲、未實機畫面驗收。

## 範圍不是幾個字

本次按完整的現有翻譯詞庫、Hook 譯文與資源內 zh_tw / zh_hk 語言文字建立字元集合，並掃描既有主／附加資源包及 SAOUI 2.41.2、SAOJob 1.1.3、SAOBlessing 1.1.0、sao-ui-lib 1.0.7 的字型定義。最終需保證顯示的中文集合是 **1,996 個漢字**，而非只指定「田、匪、氾、嶄」。

原包的 26 套 MSDF 圖集覆蓋不一致，有些字在 Work Sans 存在卻未加入其他介面字型。另一方面，33 個漢字碼被 bitmap provider 用來表示伺服器圖示。「田」對應到 hsur:required/ui/menu_banner.png（height=256、ascent=-14），會讓含該字的任務標題走到大橫幅與錯誤字寬路徑。

## 已完成的資源修復

| 項目 | 結果 |
|---|---:|
| 已檢查並補齊的 MSDF 圖集 | 26 |
| 完整現有詞庫／介面中文用字集合 | 1,996 |

| 具備可用中文字形並建立獨立顯示字碼 | 30 |

18 套 SAOUI 非 Work Sans 圖集各補 186 筆，4 套 SAOUI Work Sans 各補 36 筆，4 套 SAOJob 各補 310 筆。一般與粗體都從既有 Noto CJK 衍生來源取字，不混用另一種字體來補缺漏。舊的 Latin 與已有字形像素區域逐位元組保留；追加後最高圖集為 8,024 像素，不超過 8,192 的建置上限。

另將完整中文字體備援放在 Unifont 前，仍保留原 bitmap 圖示優先權；既有所有字型定義也加上只含安全別名字碼的字體 provider，讓沒有走 MSDF 的入口能辨識同一對照。這裡的安全別名字體沒有普通漢字或英數 cmap，不能誤吃原生圖示字碼。

## 已完成的程式修復

新增 LiteralGlyphs（外部相容模組）與 LiteralGlyphBridge（Runtime），統一舊版翻譯入口和新 Hook 引擎的顯示字碼處理：

- 只將已翻譯內容新增的衝突漢字轉到專用顯示字碼，原始伺服器圖示、未改變的文字和玩家 ID 不做全域替換。
- 保留舊的「並／中／串」顯示字碼；其他字碼從實際資源庫的未佔用區域配置，不在程式中逐字硬寫。
- 正常文字和圖示仍能共存；若來源同時使用同一漢字碼作圖示與文字，無法安全辨識時保留原碼，不猜測哪個位置是圖示。
- 顯示用字碼可以還原成可讀原文，用於重複攔截時的字典查找和中文斷行。字寬量測與繪製始終使用同一份字形資料。
- 新安全字碼沿用文字顏色，不再被既有「私人使用區即圖示」判斷當成不應著色的圖片。
- 啟用前檢查目前選用、已由下載器驗證的資源包內之 glyph-routing.json，確認 26 套圖集都有完整別名和對應檔案雜湊。舊包沒有該規格時不輸出新字碼，避免升級順序錯誤導致方框。
- 渲染熱路徑不讀檔或下載，僅使用已發布的不可變記憶體對照。

原本固定的 SAO_ZH_Agent_v16.jar 不需要修改；本次要搭配更新的是 **外部 Runtime、外部 Compatibility、主資源包和附加資源包**。只有更新翻譯 JSON 並不足以生效。

## 防止下一批譯文再次缺字

新增 test_glyph_coverage_guard.py 和已驗證的 glyph-coverage.json。未來詞庫或 Hook 新增尚未在覆蓋表內的漢字，測試會失敗並要求重建字形，不再依賴玩家回報特定字元。

建置器 build_glyph_contract_pack.py 自動從完整語料計算需求；若舊 MSDF master 沒有某個新字，就使用完整授權字體生成補充圖集。建置器拒絕直接覆蓋已有候選包，也拒絕把已套用字碼對照的包再當成原始包疊加修改。

## 驗證結果

- 修正前原包的 8 個資源檢查測試出現 97 個失敗案例；候選包的同組 8 個測試全部通過。
- 完整 Python：client-framework 124 項（5 項依環境略過）、repo 30 項；合計 **149 項實際執行通過、5 項略過**。
- Java LiteralGlyphsContract：**254 項斷言通過**，覆蓋所有 30 個別名、原圖示保留、文字顏色、數字／格式、舊版 RuntimeBridge、語言界線及缺少相符資源包時不輸出新字碼。
- Java GlyphRoutingEndToEnd：**11 項斷言通過**，實際以 bootstrap classloader 載入相容模組，由 Engine 翻譯到圖示隔離、字典重複查找及中文分行完成測試。
- Runtime 和 Compatibility 全量 Java 17 目標編譯通過；現有 120 個候選 Hook／30 個原始目標 class 位元碼驗證通過。
- 原圖示 provider、未改動資源 CRC、字形範圍、各字型完整覆蓋、資源 SHA-256 驗證通過。
- 本輪沒有啟動 Minecraft，也沒有遊戲內 GPU／畫面與 FPS 驗收。不得把離線成功說成當前伺服器畫面已修好。
